# Установка Sphinx в уже существующий репозитарий

**Sphinx** - генератор технической документации, который умеет собирать статические HTML‑страницы из текстовых исходников. Чаще всего его используют для документации к ПО — особенно в Python‑экосистеме.

Процесс выглядит следующим образом:

1. **Исходные файлы** с контентом (обычно в формате reStructuredText, RST; можно и Markdown через расширение MyST Parser)
2. **Конфигурация** (`conf.py`) — тема, язык, расширения, пути, настройки поиска и т.д.
3. **Структура оглавления** (`index.rst` + `toctree`) — задаёт иерархию страниц и связи между ними
4. **Сборка** (команда `sphinx-build` или `make html`) — Sphinx читает исходники, обрабатывает директивы и ссылки, генерирует папку со статическими HTML‑файлами, CSS, JS и картинками
5. **Публикация** — полученную папку можно выложить на любой хостинг для статических сайтов (GitHub Pages, Netlify, Vercel и т. п.).

Создаётся полностью статический сайт: никаких серверных скриптов, баз данных или динамических запросов.

Ключевые возможности для статического сайта:

- **Форматы вывода**: HTML (для сайта), PDF (через LaTeX), EPUB, man‑страницы и др
- **Перекрёстные ссылки и навигация**: оглавление, поиск по сайту, якоря, ссылки между разделами
- **Автоматическая документация по коду**: расширение `autodoc` берёт описания прямо из docstring в коде (особенно удобно для Python)
- **Директивы и блоки**: примеры кода, предупреждения, советы, математические формулы, таблицы, диаграммы (через расширения)
- **Темы оформления**: есть встроенные темы и множество сторонних; можно кастомизировать CSS/шаблоны

## Пример подготовленной конфигурации

Предположим, что в репозитарии, размещённом на локальном диске, есть файлы из которых можно собрать HTML-документацию. Например, проект документации может находится в папке `d:\Sources\FS365\docs\HTML_consumer_ProATM`. Следует обратить внимание, что в этой папке находится файл `requirements_sphinx.txt`, в котором хранятся зависимости Sphinx.

Пример файла:

```txt
alabaster==1.0.0
babel==2.18.0
certifi==2026.6.17
charset_normalizer==3.4.7
colorama==0.4.6
docutils==0.22.4
idna==3.18
imagesize==2.0.0
jinja2==3.1.6
markupsafe==3.0.3
packaging==26.2
pygments==2.20.0
requests==2.34.2
roman_numerals==4.1.0
snowballstemmer==3.1.1
sphinx_rtd_theme==3.1.0
sphinx==9.1.0
sphinxcontrib_applehelp==2.0.0
sphinxcontrib_devhelp==2.0.0
sphinxcontrib_htmlhelp==2.1.0
sphinxcontrib_jquery==4.1
sphinxcontrib_jsmath==1.0.1
sphinxcontrib_qthelp==2.0.0
sphinxcontrib_serializinghtml==2.0.0

```

Установить зависимости лучше в отдельное окружение, чтобы не засорять базовое окружение:

```shell
cd d:/Sources/FS365/docs/HTML_consumer_ProATM
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements_sphinx.txt
```

Команда сборки документации выглядит следующим образом:

```shell
sphinx-build -b html source _build
```

Альтернативная команда: `python -m sphinx -b html source _build`

Результат команды будет сформирован в папке "_build".

## Генерация документации по коду проекта на C#

Делается это через связку: **Doxygen** (разбирает C#-код) → Sphinx (рендерит документацию). Напрямую Sphinx C# не понимает, поэтому нужен "мост". Классическое решение — расширение **Breathe**, которое подключает XML‑вывод Doxygen к Sphinx.

Что понадобится:

- Python + Sphinx
- Doxygen (он и парсит C#)
- Breathe (и по желанию — exhale, чтобы автоматически сгенерировать весь API)

```shell
pip install sphinx breathe exhale
```

Doxygen устанавливается отдельно:

- в Windows с [сайта doxygen.nl](https://doxygen.nl/)
- в Linux командой `apt install doxygen`

## Альтернативы

Для C#-мира существует более "родная" экосистема — это **DocFX** и **Sandcastle** (docfx/DevDocs): они генерируют документацию напрямую из `///`-комментариев и XML‑файлов сборок, без промежуточного Doxygen. При преимущественной работе в экосистеме .NET, DocFX может оказаться проще.

Sphinx стоит выбирать, если:

- документация на нескольких языках (например, C# + Python)
- нужна мощная система перекрёстных ссылок и тем Sphinx
- документация уже частично написана в RST/Markdown
