## Atomic-операции в C++

В C++ атомарные операции реализованы через шаблон `std::atomic<T>` (заголовок `<atomic>`) и позволяют выполнять операции над переменными без гонок данных в многопоточной среде. Компилятор и процессор гарантируют, что такая операция выполнится как единое неделимое действие.

### Базовые возможности `std::atomic`

- **Чтение/запись**: `load()`, `store()`, а также операторы `operator T()` и `operator=` (но лучше использовать явные методы, чтобы контролировать порядок памяти).
- **Модификации**: `fetch_add`, `fetch_sub`, `fetch_and`, `fetch_or`, `fetch_xor` — возвращают старое значение и атомарно обновляют переменную.
- **Обмен**: `exchange()` — атомарно заменяет значение и возвращает старое.
- **Сравнение и замена (CAS)**: `compare_exchange_weak` и `compare_exchange_strong`.

## Что такое CAS (Compare-and-Swap)

CAS — это примитив синхронизации: "если текущее значение равно ожидаемому, то запиши новое". В C++ он представлен двумя методами:

```cpp
bool compare_exchange_weak(T& expected, T desired,
                           std::memory_order success,
                           std::memory_order failure);

bool compare_exchange_strong(T& expected, T desired,
                             std::memory_order success,
                             std::memory_order failure);
```

**Разница между weak и strong:**
- `weak` может вернуть `false` даже если значение совпадает (т. н. "spurious failure") — это нужно для некоторых архитектур, где так эффективнее. Обычно используется в циклах.
- `strong` гарантирует, что `false` вернётся только если значение действительно не совпало.

## Простой пример с CAS

Классический пример — реализация атомарного инкремента через CAS:

```cpp
#include <atomic>
#include <thread>
#include <iostream>

int main() {
    std::atomic<int> counter{0};

    auto inc = [&counter]() {
        for (int i = 0; i < 10000; ++i) {
            int old_val = counter.load(std::memory_order_relaxed);
            int new_val = old_val + 1;
            while (!counter.compare_exchange_weak(old_val, new_val,
                                                  std::memory_order_acq_rel,
                                                  std::memory_order_acquire)) {
                // old_val автоматически обновляется на актуальное значение
                new_val = old_val + 1;
            }
        }
    };

    std::thread t1(inc);
    std::thread t2(inc);

    t1.join();
    t2.join();

    std::cout << "Counter: " << counter.load() << "\n"; // Ожидается 20000
}
```

Здесь `old_val` передаётся по ссылке: если CAS не удался, он получает текущее значение, и мы пробуем снова.

**CAS-цикл решает проблему гонки**, но не делает весь алгоритм потокобезопасным: нужно продумывать логику и избегать ABA-проблем (когда значение меняется `A → B → A`, и CAS ошибочно считает, что ничего не менялось).

ABA возникает, когда между чтением и CAS значение успевает измениться и вернуться обратно. Это ломает некоторые lock-free алгоритмы (например, со стеками).

Способы борьбы:
- **Использовать указатели с тегами**: хранить счётчик версии вместе с указателем (иногда делают объединение в 64-битном типе)
- **Использовать специализированные структуры**, где ABA учтён (например, `std::atomic_ref` в новых стандартах или готовые lock-free контейнеры)
- **Избегать ситуаций**, где ABA критично, или использовать мьютексы там, где простота важнее максимальной производительности

## Практические советы

- **Чаще всего не нужно писать свой CAS‑цикл**: для простых операций (инкремент, декремент, сложение) рекомендуется использовать готовые `fetch_add` и т. п. — они проще и надёжнее
- **CAS нужен**, когда логика зависит от текущего значения и должна быть атомарной (например, реализация собственного lock-free стека, очереди, счётчика ссылок)
